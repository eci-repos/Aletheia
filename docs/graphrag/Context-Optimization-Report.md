## Purpose

This document describes how Aletheia LazyGraphRAG optimizes context generation to minimize token consumption while maximizing retrieval quality.

---

## Optimization Layers

### Layer 1: Corpus Search (BM25 Ranking)

Before any LLM work begins, `CorpusDiscoveryIndex.SearchCorpus(query)` identifies the most relevant source documents using BM25 scoring. This narrows the candidate pool without token cost.

### Layer 2: Query-Time Entity Discovery

Only entities relevant to the query are discovered. This avoids indexing-time entity extraction bloat.

### Layer 3: Subgraph Pruning

Low-relevance nodes and edges are removed before context generation. Default threshold: 0.25.

### Layer 4: Budget Enforcement

`IGraphTraversalBudget` caps token consumption at 4000 tokens by default.

### Layer 5: Multi-Source Context Building

`IGraphContextBuilder.BuildContextAsync` selectively includes sources based on `GraphContextSources` flags:

```csharp
GraphContextSources.Entities | 
GraphContextSources.Communities | 
GraphContextSources.Summaries | 
GraphContextSources.Relationships
```

This prevents inclusion of irrelevant source types.
