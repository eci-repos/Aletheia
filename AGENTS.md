## Wiki / Document Briefs (Sprint 55+)

- The user-facing surface is **Wiki** (never "WRAGS"); "WRAGS" is reserved for internal code/logs/docs.
- Document briefs are per-document, plain-language wiki pages (generated_from = 'document-brief', primary_source_id = document, source_ids = [document id]) generated by DocumentBriefService/SemanticKernelDocumentBriefGenerator (RAGS.Application) through an IngestionJobService background job (kind DocumentBriefs). They open with the document's nature/purpose (opening chunks) and follow the canonical template's ordered sections, cited.
- Briefs trigger after ingestion (RepositoryKnowledgeSourceIngestionService.EnsureIngestedAsync success and upload ingestion jobs) and via POST /api/wiki/briefs/regenerate (optional body { sourceId, sourceName }; omit for all documents).
- Wiki search/recent excludes community summaries (generated_from = 'graphrag') and orders document briefs first; community summaries stay internal.
- Internal search surfaces (raw Wiki/WRAGS modes, GraphRAG, LazyGraphRAG, global-graph) are gated by FeatureFlags:ShowInternalSearch (default false). Gated endpoints return HTTP 404; the Web UI hides the controls. InternalSearchGate (RAGS.Application) is the single source of truth for the flag.
- DocumentBriefService depends on IDocumentBriefGenerator; register both as singletons with the other RAGS services.

## Duplicate Uploads / Document Updates (Sprint 56)

- Uploads are fingerprinted server-side with SHA-256 before any storage write; the hash is persisted in `file_metadata.content_hash` (`init.sql` + idempotent migration `src/Repository.Infrastructure.PostgreSQL/Migrations/2026-08-05-file-metadata-content-hash.sql`).
- `IDuplicateDetectionService` (singleton, `Aletheia.Repository.Application`) resolves the newest row with the same content hash. Exact-duplicate new uploads return HTTP 409 `{ duplicate, noChange, message, existingFileId, existingFileName, existingUploadedAt, existingVersion }`; nothing is stored or ingested. The Web Upload page shows "Duplicate - already exists" and skips ingestion tracking.
- Document updates use `POST /api/files/upload` with optional `existingFileId`: same hash = no-change 409; changed file = named version snapshot (IVersioningUseCase), blob + unversioned metadata row replaced (same fileId), ingestion job enqueued with the same sourceId.
- Replace semantics live in `RepositoryKnowledgeSourceIngestionService.EnsureIngestedAsync`: before RAGS ingestion it calls `IUploadedContentKnowledgeIndexer.DeleteSourceAsync` and `IGraphProvider.DeleteSourceAsync` (Neo4j: DETACH DELETE on `n.sourceId`); `RagsService.IngestAsync` already replaces embeddings. The document-brief trigger then regenerates the Wiki brief.
- `GET /api/files/duplicates` (role Administrator) lists rows sharing a content hash for manual cleanup; no automatic deletion.
- Versioning is metadata-level: `GET /api/versions` lists history, but all versions share the single MinIO blob per fileId (documented limitation).

# GraphRAG Infrastructure Patterns

## Singleton Registration Rule
- `IGraphProvider` is registered as a singleton in DI. Any service that depends on it should also be registered as a singleton to avoid scoped/singleton capture issues.
- This applies to: `GraphSummaryService`, `HierarchicalSummaryService`, `CommunityDetectionService`, `CitationPathService`, `GraphContextBuilder`, `GraphAdminService`.

## GraphNode / GraphEdge Model
- Namespace: `Aletheia.KnowledgeGraph.Abstractions.Models`
- `GraphEdge` property is `RelationshipType`, not `Type`.
- Source nodes use `Type == "Source"`.
- Entity-to-source edges use `RelationshipType == "found_in"`.
- `GraphNode` properties dictionary keys: `"sourceId"`, `"sourceName"`, `"communityId"` for metadata tracking.

## Result<T> Pattern
- From `Aletheia.Foundation.Shared`.
- Use `Result.Success()`, `Result.Failure(string)`, `Result<T>.Success(value)`, `Result<T>.Failure(string)`.
- Check `IsSuccess` / `IsFailure` and `Value` on results before proceeding.

## Controllers
- Follow existing ASP.NET Core pattern in `Repository.API.Controllers`.
- Return `BadRequest(new { error = result.Error })` on failure.
- Use `[Route("api/...")]` attribute routing.

## Graph Explorer Render Contract (Sprint 59)
- `window.initGraph(containerId, nodes, edges, dotNetRef, preservePositions)` (in `wwwroot/index.html`) renders the cytoscape graph. `preservePositions` keeps existing node positions on scope changes (`randomize: false`) so the view does not jump around; the JS hooks `layoutstop` to invoke `dotNetRef.invokeMethodAsync('OnGraphLayoutSettled')`.
- `GraphExplorer.razor` owns a `DotNetObjectReference<GraphExplorer>` (created in `OnAfterRenderAsync` firstRender, disposed in `Dispose`) and exposes `[JSInvokable] OnGraphLayoutSettled()` which clears the `_isLoadingGraph` overlay. The page shows a spinner + staged status ("Loading graph…" → "Loading edges…" → "Rendering layout…") and disables the graph-action buttons while loading.

## GraphRAG / LazyGraphRAG Budget, Tokens, and Trace (Sprint 60)
- **Budgets are per-request, never singletons.** `GraphTraversalBudget` implements `IGraphTraversalBudget.CreatePerRequest()` (fresh budget with the same limits). `LazyGraphRagService` holds a `_budgetTemplate` and calls `CreatePerRequest()` inside `RetrieveAsync`; `GraphRagService.RetrieveAsync` constructs `new GraphTraversalBudget()` inline. There is **no** `AddSingleton<IGraphTraversalBudget>` registration — do not re-add one. `LazyGraphRagService._indexedSources` is guarded by `lock (_indexedSourcesLock)`.
- **Token accounting**: `TokenUsageHelper.GetTotalTokens(ChatMessageContent?)` (RAGS.Application/GraphIntelligence) extracts real token usage from `ChatMessageContent.Metadata` — provider-agnostic key sets (input/output/total, camel/Pascal/snake_case), nested `"Usage"`, and reflection over provider usage objects. Call sites record via `budget?.RecordTokens(TokenUsageHelper.GetTotalTokens(response))`. **`RecordTokens` records actual consumption even when it breaches the budget** and returns `updated <= MaxTokenBudget`, so `IsExceeded()` fires and halts traversal — never "cap and ignore", or the token budget silently becomes dead code.
- **Hard deadline**: both `RetrieveAsync` paths use `CancellationTokenSource.CreateLinkedTokenSource(cancellationToken)` + `CancelAfter(budget.MaxExecutionTime)` and flow the resulting `ct` through every LLM/traversal call.
- **Noise entities**: `NoiseEntityFilter.IsNoise` (types `keyword` and `statistical-candidate`, case-insensitive) marks entities that must never persist to the graph. Applied in `LazyEntityDiscoveryService.PersistAsync`, `LazyGraphRagService.PersistDiscoveryAsync` (which also drops relationships whose endpoints are noise), `GraphRagService.IngestAsync`, and `GraphRagService.EnsureQueryTimeEnrichmentAsync`. When persisting extracted entities, always filter with `NoiseEntityFilter` first.
- **Retrieval trace**: `RetrievalTrace` (RAGS.Abstractions/Models) rides on `SearchResult.Trace` (settable, additive — keep it non-breaking). It reports strategy, LLM calls, tokens consumed, nodes visited, relationships traversed, pruning ratio, elapsed ms, and an ordered step list. Web Search Center (`SearchCenter.razor`) renders `result.Trace` on each card. LazyGraphRAG fills it from the real per-request budget; GraphRAG reports an approximate `llmCalls` count (per-call token accounting for the summary/reasoning/relationship services is a documented follow-up).
- `IGraphTraversalBudget?` and `CancellationToken` now ride through the discovery interfaces: `IEntityExtractionService.DiscoverAsync(string, IGraphTraversalBudget?, CancellationToken)`, `ILazyEntityDiscoveryService.DiscoverAtQueryTimeAsync(...)`, `ILazyRelationshipDiscoveryService.DiscoverAtQueryTimeAsync(...)`. Keep the budget/`ct` parameters when touching these call sites.

## Knowledge Theme Filtering (Sprint 58) / Multi-Theme + Shared Scope (Sprint 59)

- Theme = category label on a canonical template (e.g., `3.0 - RFP Analysis` -> `Analysis`). Templates in `docs/doc-templates` declare a **theme set** on the first line (`Theme: Analysis, As-Built`, comma-separated; a single value remains valid). `DocumentTemplateRegistry` exposes `TryGetThemes(fileName)` -> `IReadOnlyList<string>?` and `ListThemes()` (flattened, distinct; missing/mismatched => `Uncategorized`).
- `file_metadata` persists `template_name` + `theme` (`text[]`) + `template_status` (`Canonical`/`Uncategorized`) — idempotent migration `src/Repository.Infrastructure.PostgreSQL/Migrations/2026-08-07-file-metadata-template-status-themes.sql` (casts existing TEXT `theme` to `text[]`, GIN index) + init.sql. Ingestion writes them in `RepositoryKnowledgeSourceIngestionService`; `SetTemplateAsync` persists all three. Read-time fallback derives the theme set from the file name via the registry, but only as a safety net — persisted values win.
- Theme resolution: `IKnowledgeThemeService.ResolveSourceIdsAsync(IReadOnlyList<string> themes)` (singleton) matches a row when **any** of its themes is in the requested set; `GetThemesWithCountsAsync` counts a document in **each** of its themes. Used by Copilot (session filter) and Search Center (shared scope).
- Session scoping (Copilot): `ChatSession.ThemeFilter` (empty = all documents) rides `ChatPayload` -> `ChatRequestOptions` -> `ChatExecutionEngine`; the engine resolves themes to source ids via `ResolveSourceIdsAsync` and enforces them in the RAGS retrieval paths via `RetrievalRequest.SourceIds` (PgVectorStore `source_id = ANY(...)` predicate on both `SearchAsync` and `SearchKeywordAsync`). Named-document scope (Sprint 51) intersects with the theme filter; collection paths take the union of theme-matched sources.
- Shared scope (Search Center): `SearchScopeStateService` (scoped, localStorage `aletheia.search.scope.v1`) holds a shared theme selection (empty = all). Search Center applies it to **semantic** search via `GET /api/rags/retrieve?themes=` (controller resolves -> `RetrievalRequest.SourceIds`) with a visible "Scoped to N themes" indicator. Since Sprint 64 the scope also applies to **GraphRAG / LazyGraphRAG / global-graph** modes (see the Sprint 64 section below). Copilot keeps its session-scoped filter; Wiki stays curated.
- Uncategorized admin surface: `GET /api/knowledge/uncategorized` lists non-Canonical rows; `POST /api/knowledge/reevaluate` re-resolves the template for one or all (backfill + promotion), persists `template_name`/`theme`/`template_status`, and enqueues a document brief for rows that become `Canonical`. `TemplateReevaluationService` (singleton) implements it.
- `GET /api/knowledge/themes` (authenticated) returns `[{ theme, documentCount }]` for the UI pickers. Web: theme chips in Copilot session header persisted in `CopilotStateService` (localStorage `aletheia.copilot.session.v2`); theme filter chips in Search Center persisted in `SearchScopeStateService`.
- `GET /api/rags/status` diagnostics report uncategorized ingests (`UncategorizedIngestCount`/`UncategorizedIngests`) so operators can see documents awaiting a template.
- Copilot plan-progress contract: `GET /api/copilot/plans/{planId}/progress` returns **200 with `JobId == Guid.Empty`** when the plan exists but has no execution job yet (the normal "waiting for approval" state); "plan not found" is a 404. The Web polling loop (`Index.razor` `StartProgressPollingAsync`/`RefreshProgressAsync`) treats empty `JobId` as "not started" — it clears stale restored execution state, keeps the plan preview, and stops polling after 3 consecutive no-progress polls. Chat plans and execution jobs are both in-memory (`InMemoryChatPlanRepository`, `InMemoryChatProgressStore`), so a container restart invalidates any browser-restored plan/job; the client must fall back to the plan preview instead of polling forever.

## Reembed Parity and GraphRAG Soft Deadline (Sprint 62)

- **`KnowledgeIndexMode`** (`Aletheia.RAGS.Abstractions.Models`, `Full`/`Lightweight`): `IKnowledgeSourceIngestionService.EnsureIngestedAsync(source, ct, mode = Full)` — `Full` runs `UploadedContentKnowledgeIndexer.IndexAsync` (LLM graph intelligence), `Lightweight` runs `IndexLightweightAsync` (no LLM; deterministic topic extraction, taxonomy tags, ontology source+topic entities, graph seed nodes with `lazyEnrichmentStatus="Pending"`). **Reembed** (`RunReembedJobAsync`) passes `KnowledgeIndexMode.Lightweight` — its job is regenerating embeddings, not re-deriving graph intelligence; **repair** (`RunRepairJobAsync`) and chat-hydration callers keep the default `Full`.
- **GraphRAG soft deadline**: `GraphRagService.RetrieveAsync` still enforces the 30s hard deadline (`CancelAfter(MaxExecutionTime)`), but it distinguishes **deadline-fires** (`timeoutCts.IsCancellationRequested && !cancellationToken.IsCancellationRequested`) from **caller-cancel**: on deadline it runs a best-effort plain semantic retrieval under a short secondary deadline and returns `Success` with trace strategy `semantic-timeout-fallback` and steps `deadline-exceeded`/`semantic-fallback`; caller-cancel and other exceptions still fail. The degrade is centralized in `RunSemanticTimeoutFallbackAsync` and fires from **both** the thrown-exception catch path **and** the returned-Failure base-retrieval path — `PgVectorStore` converts a cancelled vector search into a returned `Failure` (not a thrown `OperationCanceledException`), so check the deadline condition on `baseResults.IsFailure` too or a deadline becomes HTTP 400 again (fixed `88164e4`). The constructor takes an optional `Func<IGraphTraversalBudget>? budgetFactory` (default `() => new GraphTraversalBudget()`) so tests can inject a short-deadline budget. Keep this degradation behavior in mind when touching the retrieval path — a deadline is no longer an HTTP 400.

## Persisted LazyGraphRAG Corpus Index and Batch GraphRAG Ingest (Sprint 63)

- **Corpus index persistence**: `ICorpusIndexRepository` (`Aletheia.RAGS.Abstractions.Interfaces`, `UpsertDocumentAsync(sourceId, termFrequency, documentLength, ct)` + `LoadAsync(ct)`; models `CorpusIndexSnapshot`/`CorpusDocumentIndex`) → `PostgreSqlCorpusIndexRepository` (`Aletheia.RAGS.Infrastructure.PostgreSQL.CorpusIndex`, Dapper + `PostgreSqlConnectionFactory`). Tables `lazygraphrag_corpus_documents` (source_id PK, document_length, updated_at) + `lazygraphrag_corpus_terms` (source_id FK ON DELETE CASCADE, term, frequency, PK (source_id, term)) — idempotent migration `src/Repository.Infrastructure.PostgreSQL/Migrations/2026-08-11-lazygraphrag-corpus-index.sql` + `scripts/init.sql` in sync. `CorpusDiscoveryIndex` ctor takes `(ICorpusIndexRepository? repository = null, ILogger<CorpusDiscoveryIndex>? logger = null)`: loads the persisted corpus at startup and persists write-through on `IndexAsync`. **Both are best-effort** — a load/persist failure logs a warning and never fails ingestion; the in-memory index stays authoritative. Registered `AddSingleton<ICorpusIndexRepository, PostgreSqlCorpusIndexRepository>()` in `Program.cs`.
- **Batch graph writes**: `IGraphProvider` gained `CreateNodesAsync(IReadOnlyList<GraphNode>)`, `CreateRelationshipsAsync(IReadOnlyList<GraphEdge>)`, `UpdateNodesAsync(IReadOnlyList<GraphNode>)` with **default interface implementations** that fall back to per-item calls — so existing test fakes (`MockGraphProvider`, `MemoryGraphProvider`) keep compiling without changes. `Neo4jGraphProvider` implements them with `UNWIND $rows AS row` Cypher, grouping nodes/updates by `BuildNodeLabels(type)` and relationships by `NormalizeToken(RelationshipType, "related_to")` (dynamic labels/types can't be set per-row in a single UNWIND). Prefer the batch methods for multi-write ingest paths.
- **Bounded-concurrency ingest**: both full-ingest paths (`UploadedContentKnowledgeIndexer.PersistGraphIntelligenceAsync` and `GraphRagService.IngestAsync`) run 4 phases with `private const int MaxLlmConcurrency = 4` (`SemaphoreSlim` + `Task.WhenAll`): (1) bounded per-chunk entity + relationship extraction (relationship pass stays sequential within a chunk), (2) build all nodes/edges then one `CreateNodesAsync` + one `CreateRelationshipsAsync` per label/type group, (3) bounded entity summaries (deduped via `createdEntityIds`), (4) **gated community detection** — `SourceNodeExistsAsync` (via `GetNodeAsync`) is checked **before** the source node is created; community detection + bounded community summaries + `UpdateNodesAsync` run only when `!sourceExists` (first ingest of a source). Re-ingests of an existing source skip the O(graph) re-cluster; retrieval-time discovery still re-clusters on cache miss. `ChunkExtraction` record `(Chunk, IReadOnlyList<ExtractedEntity>, IReadOnlyList<ExtractedRelationship>?)` is shared by both paths.

## Ingestion Status in the Repository Browser (Sprint 69)

- **Ground truth is embeddings, not job status.** A source is "ingested" when it has ≥1 embedding in the durable embeddings table; ingestion jobs are in-memory and lost on container restart, so they are never the signal. `FileMetadata.Ingested` is computed as `ChunkCount is > 0`.
- **`IVectorStore.GetChunkCountsAsync(IReadOnlyList<Guid> sourceIds, CancellationToken)`** returns `Result<IReadOnlyDictionary<Guid, int>>` (source id → chunk count). It has a **default no-op impl** (empty map) so existing fakes keep compiling; `PgVectorStore` overrides with a grouped `SELECT e.source_id, COUNT(*) FROM embeddings e WHERE e.source_id = ANY(@SourceIds) GROUP BY e.source_id`.
- **`SearchController` (Repository.API) stamps the signal** — it already hosts both modules, so no cross-module dependency is introduced. After a successful search it collects the page's distinct `Descriptor.FileId`s, calls `GetChunkCountsAsync`, and sets `file.ChunkCount` (0 when the source is missing from the map). `FileMetadata.ChunkCount` is `int?`; `Ingested` is computed.
- **Mid-ingestion "Processing" state (post-sprint 2026-08-14)**: a source with an active ingestion job is mid-flight — partial embeddings must not read as "complete". `IIngestionJobService.HasActiveIngestion(Guid sourceId)` (new interface member) is true while an active (queued/running) **upload/rag/graph/lazy-graph content job** targets the source **or** a **global** re-embed (`ReembedIngestion`) / RAGS-repair (`RagsRepair`) job is running (those reprocess every document). `SearchController` stamps `FileMetadata.IsProcessing` (bool) alongside `ChunkCount`. If you extend `IIngestionJobService`, keep the two test fakes in RAGS.UnitTests (`FakeIngestionJobService`, `FakeIngestionJobs`) implementing the new member.
- **`Browse.razor` renders a three-state Ingestion column**: blue `bg-info text-dark` **Processing** (active job still writing embeddings), green `bg-success` **Ingested** (no active job, ≥1 embedding), amber `bg-warning text-dark` **Not ingested** (no active job, 0 embeddings). Tooltips state the **embeddings-only scope** ("status reflects embeddings only") — graph/taxonomy/wiki-brief resource readiness is a documented follow-up. If you add another surface that lists uploaded files, consider surfacing the same signal.
- **Bootstrap gotcha (fixed 2026-08-14)**: the vendored `wwwroot/css/bootstrap/bootstrap.min.css` is **v5.1.0**, so `text-bg-*` utilities (Bootstrap 5.2+) **do not exist** — a `badge text-bg-success` renders as invisible white-on-white text. Use the app convention: `badge bg-success`, `badge bg-warning text-dark`, `badge bg-info text-dark`, `badge bg-light text-dark border`. Never introduce `text-bg-*` in this app.

## Query Expansion for Acronyms (Sprint 68)

- **`QueryExpander`** (`src/RAGS.Application/QueryExpander.cs`) is the single place that expands domain acronyms in a user query **before embedding**: `Expand(string)` appends the spelled-out term after each standalone acronym ("AI features" → "AI Artificial Intelligence features") so a short acronym retrieves documents that spell it out. The `Expansions` dictionary (public static, `StringComparer.OrdinalIgnoreCase`) holds the domain set — AI, GenAI, RFP, RFI, ML, LLM, NLP, API, SOW, SLA, KPI, POC, MVP, OCR, PDF, SQL, RAG. **Extend the dictionary, don't add expansion logic elsewhere.** The regex is single-pass, longest-first (`GenAI` wins over `AI`), word-boundary aware (`email`/`AIM` untouched), case-insensitive, and never re-scans an expansion's own text.
- **Embedding vs keyword split**: `RagsService.RetrieveAsync` embeds `QueryExpander.Expand(request.Query)` but the **keyword fallback keeps the original query** — `PgVectorStore.SearchKeywordAsync` is a whole-string `ILIKE '%query%'` match, so the expanded phrase would match nothing. Keep that split if you touch the retrieval path.

## Wiki Markdown and HTML View Tabs (Sprint 65)

- **Wiki pages render as markdown by default.** `WikiPage.Summary` holds markdown; `Wiki.razor` shows a **View / Source** tab bar (default View). View renders the summary via `MarkdownRenderer.ToHtml` (a `MarkupString`) — headings, tables, lists, paragraphs, inline `**bold**` and `` `code` ``. Source shows the raw markdown escaped in a `<pre class="wiki-source-view">`. The tabs are ephemeral page state (`_viewMode`), never persisted or wired through the API. Editing still uses the raw-markdown textarea.
- **`MarkdownRenderer` (`src/Aletheia.Web/Services/MarkdownRenderer.cs`) is the single markdown renderer** — a static `ToHtml(string content)` returning an HTML string. It is the extraction of Copilot's former private `RenderMarkdown` helpers: all text is `HtmlEncoder`-escaped **before** inline formatting, so raw HTML in source content is never emitted as markup. Emitted table wrappers use neutral classes `md-table-wrap` / `md-table` (styled in both `Copilot/Index.razor.css` and `Wiki.razor.css`). When a wiki/chat surface needs markdown rendering, call `MarkdownRenderer.ToHtml` — do not reimplement.
- **Copilot's JSON special case stays in `Pages/Copilot/Index.razor`**: content that trims to a `{`/`[` JSON blob renders as `<pre class="copilot-json">`; everything else delegates to `MarkdownRenderer.ToHtml`. The private table/heading/list helpers no longer live in the page.

## Theme-Aware Graph Retrieval (Sprint 64)

- **`sourceIds` scope on graph services**: `IGraphRagService.RetrieveAsync`/`GlobalSearchAsync`, `ILazyGraphRagService.RetrieveAsync`/`GlobalSearchAsync`, and `IGlobalGraphSearchService.SearchAsync` all take an optional `IReadOnlyList<Guid>? sourceIds = null` **after** `cancellationToken`. Null = no scope (behavior identical to pre-Sprint-64). When adding/updating fakes, the full parameter list must match (C# requires implementations to match optional params too).
- **`GraphThemeScope`** static helper (`RAGS.Application/GraphRAG`): `TryGetSourceId(GraphNode)` reads `Properties["sourceId"]` (Guid or string) and falls back to `Type == "Source"` → `Id`; `IsInScope(node, allowSet)`; `FilterNodes(nodes, sourceIds)`; `ToAllowSet(sourceIds)` (null/empty → null); `CommunityHasMemberInScope(community, nodeToSource, allowSet)` with **match-any** semantics (consistent with `KnowledgeThemeService.ResolveSourceIdsAsync`).
- **Enforcement points**: `GraphRagService.RetrieveAsync` filters resolved entities + multi-hop expansion nodes to the allowlist and scopes the semantic fallback / entity-expansion `RetrievalRequest`s with `sourceIds`; `LazyGraphRagService.RetrieveAsync` filters the corpus seed sources (`SearchCorpus` results) before entity discovery and scopes fallback / expansion requests; `GlobalGraphSearchService.SearchAsync` builds a node→source map via `IGraphProvider.GetNodesAsync()` and filters communities with match-any semantics — when scoped and nothing survives it returns `Failure("No communities in the selected themes.")`. `GlobalGraphSearchService` ctor gained optional `IGraphProvider? graphProvider = null` (after `kernel`) — do not reorder.
- **API + Web**: `GraphRagController`/`LazyGraphRagController` accept `?themes=` (comma-separated) on `Retrieve` and `GlobalSearch`, resolve via optional `IKnowledgeThemeService? themeService = null` ctor param (RagsController pattern), pass `sourceIds` through. `RepositoryApiClient.GraphRagRetrieveAsync`/`LazyGraphRagRetrieveAsync` accept themes and append `&themes=`. `SearchCenter.razor` passes `_selectedThemes` to graph-mode retrieve calls; the WRAGS note reads "Theme scope does not apply to WRAGS search."
